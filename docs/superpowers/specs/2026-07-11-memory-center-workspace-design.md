# 记忆中心工作区改造设计

## 背景

当前记忆中心将长期记忆、短期会话记忆、任务历史、经验、负向规则和 Skill 候选同时铺在一个双列长页面中。早期为解决卡片截断，`#memoryView .memoryPanel` 与 `#memoryView .memoryBlock` 被设置为无限展开和 `overflow: visible`。真实数据增长后，任务历史和经验会把页面拉得很长，负向规则与 Skill 候选被推到多屏以后，页面缺少明确的主任务。

## 目标

1. 将记忆中心改成有明确导航和稳定高度的管理工作区。
2. 分开呈现长期记忆、当前会话、经验规则和任务归档。
3. 任何数据量下都不再依赖无限页面增长；列表与详情在各自区域滚动。
4. 用面向用户的标题和摘要替代裸任务 ID、大段原始 Markdown 和重复经验卡片。
5. 没有当前会话时，压缩按钮必须禁用并解释原因。
6. 保留现有记忆 API、文件格式和历史数据，不迁移、不删除记录。

## 信息架构

记忆中心顶部保留页面标题，下方增加四个标签：

1. **长期记忆**：管理用户画像、偏好、工作习惯、项目事实、明确约束、决策记录和待确认问题。
2. **当前会话**：显示当前会话标题、短期摘要、消息保留量、估算 token、压缩位置和更新时间，并提供压缩与刷新操作。
3. **经验规则**：集中展示经验、负向规则和 Skill 候选，不与任务历史混排。
4. **任务归档**：使用左侧紧凑任务列表和右侧详情区查看历史任务，不再在页面中完整铺开所有输出。

标签使用标准 `role="tablist"`、`role="tab"` 和 `role="tabpanel"` 关系。切换标签只改变前端展示，不重新请求数据。

## 页面布局

`memoryView` 使用专用的 `memoryCenterWorkspace`，网格行为为：页面标题、标签栏、当前标签内容。工作区本身占满可用高度并隐藏外层溢出；每个标签面板负责自己的滚动。

### 长期记忆

采用“分类列表 + 事实详情”的左右布局。左侧显示七类记忆及条数，默认选择第一条有内容的分类；如果全部为空则选择用户画像。右侧只展示当前分类的事实，空分类显示紧凑空状态。来源详情继续保留置信度、来源会话和时间信息。

### 当前会话

使用单一聚焦面板，不显示其他历史记录。会话存在时展示摘要和压缩指标；没有当前会话时显示清晰空状态，并将“压缩当前会话”按钮设为禁用。刷新按钮始终可用。

### 经验规则

宽窗口使用三列：经验、负向规则、Skill 候选。每列有固定面板边界和独立滚动。经验按“任务类型 + 内容”去重，相同经验显示累计次数；负向规则和 Skill 候选使用专用标题与摘要，不直接暴露内部 JSON。

### 任务归档

左侧列表展示任务类型、状态、日期和简短摘要；内部任务 ID 作为次级信息。右侧显示当前任务完整详情，内容通过现有 Markdown 渲染器显示。默认选择最新任务。列表与详情独立滚动。

## 数据与状态

继续调用 `get_memory_overview` 和 `get_conversation`。前端状态增加：

- `memoryOverview`：最近一次加载的记忆数据。
- `memoryTab`：当前标签，默认 `long-term`。
- `memoryLongTermKind`：当前长期记忆分类。
- `memoryArchiveTaskId`：当前归档任务。

`renderMemoryOverview()` 负责保存数据并分别调用四个标签的渲染函数。标签切换不改变后端数据。

## 内容规则

- 任务列表标题优先使用任务类型和状态，不再以裸 `task_id` 作为主标题。
- 列表摘要去除 Markdown 标记、合并空白并限制长度；详情继续使用 Markdown 渲染。
- 经验按稳定键去重并显示次数，不修改底层记录。
- 长期记忆事实仍按原始 `kind` 分类。本次不自动修正历史上可能误分类的内容，避免无审计的数据迁移。
- 所有内部 ID 使用等宽小字作为次级信息。

## 响应式规则

- 宽度大于 `1179px`：长期记忆和任务归档使用左右双栏，经验规则使用三列。
- 宽度不大于 `1179px`：长期记忆与任务归档切换为上下布局，经验规则切换为单列；各列表仍保持受控高度和内部滚动。
- 最小桌面窗口 `960×640` 不得出现横向滚动，标签栏允许横向滚动但不换成多行。

## 测试与验收

1. 静态资产测试确认四个标签、ARIA 关系和专用布局类存在。
2. JavaScript 运行测试确认标签切换、长期分类选择、归档选择、经验去重和无会话按钮禁用。
3. 原有记忆 API 与压缩调用测试继续通过。
4. 在 `1280×820`、`1179×800`、`960×640` 三种尺寸检查无横向溢出、无无限外层页面增长、列表和详情独立滚动。
5. 全量 pytest、JavaScript 语法检查、PyInstaller 构建、签名和 zip 完整性全部通过。
