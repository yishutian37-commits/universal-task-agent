# 知识库工作区布局修复设计

## 背景

当前知识库页面直接复用了记忆页的 `memoryWorkspace`、`memoryColumn` 和历史页的 `historyItem`。这些通用样式面向记忆卡片和任务历史，不适合“文档浏览 + 问答”的工作流。在桌面应用常用窗口尺寸下，文档路径会撑高并挤压相邻卡片，文档列表与外层工作区同时滚动；右侧问答结果又继承 `.report` 的 `min-height: 420px`，形成大片无效空白。

## 目标

1. 知识库使用独立布局，不再受记忆页和历史页样式调整影响。
2. 文档列表稳定滚动，标题、类型、片段数和来源路径不会重叠。
3. 问题输入、回答和检索来源形成清晰的纵向工作流。
4. 在宽窗口保持双栏，在窄窗口自然切换为单栏。
5. 不修改 RAG 后端接口、数据结构和现有文档数据。

## 页面结构

知识库工作区使用 `knowledgeWorkspace`。页面标题横跨整行，内容区由两列组成：

- 左列 `knowledgeLibraryColumn`：文档管理面板占据主要空间，库统计作为紧凑面板放在底部。
- 右列 `knowledgeQueryColumn`：知识库问答面板占据主要空间，检索来源面板放在底部。

文档管理工具栏使用正式类名替代内联样式。文档列表使用 `knowledgeDocList`，文档条目使用 `knowledgeDocItem`，不再复用 `historyItem`。来源路径保持在一行内并显示省略号，完整路径保留在 `title` 属性中。

问答面板使用 `knowledgeQueryPanel`，输入区使用 `knowledgeQueryComposer`，回答区使用 `knowledgeAnswer`。回答区不继承通用报告的固定最小高度，而是在当前面板剩余空间内滚动。检索来源使用 `knowledgeSourcesPanel` 和 `knowledgeSources`，空状态保持紧凑。

## 响应式规则

- 宽度大于 `1179px`：左右双栏，左列约 44%，右列约 56%。
- 宽度不大于 `1179px`：沿用现有二级页面规则切换为单栏；每个面板使用内容高度，页面整体滚动。
- 文档标题和路径均允许收缩；任何长路径不得改变网格列宽或覆盖相邻条目。

## 交互与数据

保留现有 `rag_stats`、`rag_list_docs`、`rag_ingest`、`rag_ask`、`rag_query` 和 `rag_delete` 调用。只调整 HTML 结构、渲染类名和 CSS，不改变知识库数据、摄入方式、问答行为和删除确认机制。

## 验收标准

1. 当前桌面窗口中，文档条目之间无重叠，列表内部可滚动。
2. 长来源路径单行省略，完整路径可通过悬停查看。
3. 问题输入区始终在回答区上方，回答区不再制造 420px 的空白占位。
4. 检索来源与回答区域边界清晰，页面没有双重滚动造成的卡顿。
5. 前端资产测试、全量测试、PyInstaller 打包、签名检查和 zip 完整性检查全部通过。
