# UTA 模型路由与统一事件实施计划

## 目标

让桌面端的每条消息先经过模型理解，再决定进入普通聊天或任务执行；同时保留高风险工具的确定性安全边界，并逐步把聊天回复和任务进度收敛到统一事件协议。

## 实施顺序

1. 新增独立消息路由器，要求模型返回 `chat/task`、理由、置信度和可选聊天回复。
2. 对文件写入、删除、目录创建、Shell、Python REPL 等高风险请求强制进入任务通道，模型不得降级为普通聊天。
3. 模型输出无效或调用失败时，回退到现有规则路由，保证离线测试和异常场景可用。
4. 普通聊天复用路由模型已生成的回复，避免先分类再等待第二次模型调用。
5. 修正模型识别为任务后才发现未选择工作区的前端重试流程。
6. 为桌面事件增加统一信封字段，并保持旧事件消费者兼容。
7. 在 LLM 客户端和桌面端接入真实增量回复；若服务不支持流式协议，明确回退为完整回复事件。

## 验收标准

- 不依赖固定关键词也能识别模糊任务。
- “帮我想一个名字”之类请求可以作为普通聊天直接回答。
- 高风险请求即使被模型判断为聊天，也必须进入授权和任务流程。
- 模型异常时不阻断现有功能。
- 普通聊天的模型路由与回复不发生重复调用。
- 模型后判定为任务时，桌面端可提示选择工作区并自动重试一次。
- 新旧任务事件在迁移期都能被前端正确消费。
